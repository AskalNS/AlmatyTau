# Публикация прототипов для показа Заказчику

Конфигурация: Windows Server, белый IP, домена нет, доступ открытый.

---

## Вариант 0 — вообще без сервера (30 секунд)

Обе страницы **полностью автономны**: ни одного внешнего запроса, шрифты системные,
изображения нарисованы на CSS. Их можно просто заархивировать и отправить письмом —
заказчик распакует и откроет `index.html` двойным кликом.

```powershell
Compress-Archive -Path C:\...\publish\* -DestinationPath ATM-prototypes.zip
```

Минус: письмо с архивом HTML часто режут корпоративные почтовые фильтры,
а «распакуйте и откройте» — лишний барьер для руководителя. Ссылка удобнее.

## Вариант 1 — IIS на вашем сервере (основной)

### Шаг 1. Перенести папку на сервер

Скопируйте всю папку `publish` на сервер, например в `C:\deploy\publish`.
Внутри должно быть три файла: `index.html`, `ux.html`, `ui.html`.

### Шаг 2. Запустить скрипт

На сервере, в PowerShell **от имени Администратора**:

```powershell
cd C:\deploy\publish
.\deploy-iis.ps1 -Source C:\deploy\publish -SiteName atm-demo -Port 80 -OpenFirewall
```

Скрипт: доустановит роли IIS при необходимости, скопирует файлы в `C:\inetpub\atm-demo`,
выдаст IIS_IUSRS права **только на чтение**, создаст сайт, пропишет `web.config`
с UTF-8 и `noindex`, откроет порт в брандмауэре.

Если порт 80 занят другим сайтом — возьмите `-Port 8080`, ссылка станет `http://IP:8080/`.

### Шаг 3. Проверить

На сервере:
```powershell
Invoke-WebRequest http://localhost/ -UseBasicParsing | Select-Object StatusCode
(Invoke-WebRequest https://api.ipify.org -UseBasicParsing).Content   # внешний IP
```

Снаружи (с другого интернета, не из офиса — из офиса запрос может уйти в обход NAT):
откройте `http://<внешний-IP>/` с мобильного интернета.

Если локально открывается, а снаружи нет — дело не в IIS, а в одном из трёх:
брандмауэр Windows, правила облачного/хостингового firewall (Security Group),
или проброс портов на роутере.

## Шаг 4. HTTPS — это надо решить до показа

**Проблема.** Без домена сертификат не выпустить, и заказчик увидит в адресной строке
предупреждение **«Не защищено»**. Показывать материалы по тендеру, где п. X.I ТЗ прямо
требует SSL и обязательный HTTPS, по незащищённому соединению — плохой сигнал.
Комиссия оценивает в том числе то, как подрядчик сам обращается с безопасностью.

Три способа закрыть это, от лучшего к быстрому:

### А. Купить домен (рекомендую)

Домен всё равно понадобится для боевого сайта — этап 5 ТЗ требует передать Заказчику
доступы к доменному имени. Регистрация `.kz` или `.com` — от 3 000 ₸ / ~10 $ в год.

```
demo.вашдомен.kz  →  A-запись на белый IP сервера
```

Дальше бесплатный сертификат Let's Encrypt через **win-acme** (https://www.win-acme.com):

```powershell
.\wacs.exe --target iis --siteid <ID> --installation iis --accepttermsofservice
```

Сертификат продлевается сам, задание в планировщике создаётся автоматически.
Итог: `https://demo.вашдомен.kz` без предупреждений.

### Б. Бесплатный поддомен DuckDNS (если домен покупать не хочется)

Регистрация на https://www.duckdns.org — бесплатно, поддомен вида `atm-demo.duckdns.org`,
указывающий на ваш IP. Let's Encrypt для него выпускается штатно (через DNS-01 в win-acme).
Стабильная ссылка, полноценный HTTPS. Выглядит менее солидно, чем свой домен, но
предупреждения в браузере нет.

### В. Cloudflare Tunnel (быстрее всего, 5 минут)

Не требует ни домена, ни открытых портов, ни настройки брандмауэра:

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:80
```

В консоли появится готовая ссылка `https://<случайное-имя>.trycloudflare.com` — сразу
с валидным сертификатом. Отдаёте её заказчику.

Ограничения: ссылка живёт, пока запущен процесс, и меняется при перезапуске.
Годится для показа на созвоне, не годится как «оставлю вам ссылку на неделю».

## Безопасность сервера

Материалы решено оставить открытыми — это нормально, но сам сервер стоит проверить.
Публикуя порт 80 наружу, убедитесь, что заодно наружу не смотрит лишнее:

```powershell
# что вообще слушает наружу
Get-NetTCPConnection -State Listen |
  Where-Object LocalAddress -in '0.0.0.0','::' |
  Select-Object LocalPort, @{n='Процесс';e={(Get-Process -Id $_.OwningProcess).ProcessName}} |
  Sort-Object LocalPort
```

Особое внимание — порту **3389 (RDP)**. Открытый в интернет RDP подбирают ботами
в течение суток. Если он открыт — ограничьте правилом брандмауэра по вашему IP
или уберите за VPN.

## Чек-лист перед отправкой ссылки

- [ ] `http://<адрес>/` открывается с постороннего интернета, не только из офиса
- [ ] Обе карточки на титульной странице кликаются, прототипы грузятся
- [ ] Кириллица отображается корректно (не «кракозябры») — за это отвечает `web.config`
- [ ] Кнопки Desktop / Mobile переключают вид
- [ ] Проверено в Chrome, Edge, Firefox, Safari — п. VII ТЗ требует именно этот набор
- [ ] Открыто с телефона
- [ ] HTTPS настроен, предупреждения «Не защищено» нет
- [ ] RDP не смотрит в интернет
