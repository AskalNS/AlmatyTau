# Локальное тестирование

Стек уже запущен через `docker compose up -d --build`. Файл
`docker-compose.override.yml` публикует порты сервисов на `localhost`
(только для разработки, в бой не идёт).

## Точки доступа

| Что | Адрес | Примечание |
|---|---|---|
| Публичный сайт | http://localhost:3000/ru | языки: `/ru`, `/kk`, `/en` |
| Админ-панель | http://localhost:3001 | вход ниже |
| Документация API (Swagger) | http://localhost:4000/api/docs | все эндпоинты, п. II ТЗ |
| Консоль хранилища MinIO | http://localhost:9001 | логин/пароль из `.env` (S3_ACCESS_KEY / S3_SECRET_KEY) |
| Через nginx (как в бою) | http://localhost/ru, http://localhost/api/... | доменная маршрутизация |

## Вход в админку

Открыть http://localhost:3001, ввести:

- **E-mail:** значение `SEED_ADMIN_EMAIL` из `.env`
- **Пароль:** значение `SEED_ADMIN_PASSWORD` из `.env`

При первом входе система попросит сменить временный пароль. Двухфакторную
аутентификацию можно подключить в профиле (для администратора это требование
п. X.II ТЗ).

## Сквозной сценарий проверки

1. Войти в админку → раздел **Новости** → «Создать».
2. Заполнить вкладку **RU** (заголовок, анонс, блоки), при желании — **KK** и **EN**.
   Языки без заполнения не публикуются (п. III ТЗ) — видно по индикатору `✓ / —`.
3. Нажать «Опубликовать».
4. Открыть сайт http://localhost:3000/ru/media/news — новость появится в ленте.
5. Переключить язык на `/kk` — если казахскую версию не заполняли, новости на
   казахском не будет (это корректное поведение, а не ошибка).

## Проверка API напрямую

```bash
# здоровье сервиса
curl http://localhost:4000/api/health

# публичные данные (меню, настройки) на трёх языках
curl "http://localhost:4000/api/public/layout?locale=ru"
curl "http://localhost:4000/api/public/home?locale=kk"
curl "http://localhost:4000/api/public/news?locale=en&limit=5"

# вход (вернёт токены или запрос кода 2FA)
curl -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@atm.kz","password":"<из .env>"}'
```

## Полезные команды

```bash
docker compose ps                    # статус сервисов
docker compose logs -f backend       # логи бэкенда
docker compose logs -f web           # логи сайта
docker compose restart backend       # перезапуск сервиса
docker compose down                  # остановить всё (данные в томах сохранятся)
docker compose down -v               # остановить и удалить данные (чистый старт)
```

## Проверка мобильной версии и доступности

- В браузере: DevTools → режим устройства (адаптивность, п. VII ТЗ).
- Версия для слабовидящих: кнопка «Версия для слабовидящих» в шапке сайта
  либо `http://localhost:3000/ru?a11y=on`.
- PageSpeed: https://pagespeed.web.dev по временному публичному адресу
  (локальный localhost сервис измерить не даст — нужен доступный извне URL).

## Замечания для локального теста

- Почта (форма обратной связи, приглашения пользователей) при пустом `SMTP_HOST`
  никуда не уходит — это норма для локали. Для проверки писем поднимите Mailpit
  из `docker-compose.dev.yml` и укажите `SMTP_HOST=mailpit`.
- Поиск (`/api/public/search`) индексирует контент при публикации через админку.
  Демо-новости из сида созданы напрямую в БД и в индекс не попадают — создайте
  запись через админку, чтобы проверить поиск.
